Crypto Pipeline

What it does: fetches spot prices for a batch of coins and processes a historical price stream (live source: CoinGecko's public simple/price endpoint, no API key).

Architecture, in 5 lines: fetch_prices_with_dlq() fetches each coin independently → a per-coin failure is routed to a DeadLetterQueue, not raised → replay_dlq() retries only the dead-lettered coins → separately, process_chunked() consumes a historical-price stream in bounded chunks so a mid-stream failure loses at most one chunk, not the whole run.

What this proves — see BUILD_LOG.md for the full postmortem on each: 1. Dead-letter queue + replay — one failing coin never takes down the rest of the batch, and the failure is recorded, not silently dropped. 2. Chunked processing at scale — a stream that fails partway through preserves everything processed before the failure, and reports exactly how far it got.

Run it yourself:

pip install -r ../../requirements.txt
pytest tests/ -v          # deterministic, no network required
python pipeline.py --live # hits the real CoinGecko endpoint

What this is / isn't: a small demonstration pipeline built to make two specific, realistic production failure modes concrete and testable — not a trading system, not investment advice, not a claim that this is any specific employer's actual architecture.

Build Log — the postmortem

Build Log — Crypto Pipeline

Postmortem-style log (Issue / Impact / Root Cause / Fix / Prevention) — see ../../EVALUATION_RUBRIC.md.

Issue #3 — One failed coin fetch aborts the entire batch, silently

Found: while testing behavior when a single coin ID in a multi-coin batch fails (a genuinely invalid ID, or a transient rate-limit/timeout from CoinGecko on just that request).

Impact: the naive batch fetch has no per-item failure isolation — one bad coin ID raises and the whole batch call fails, discarding results for every other coin that had already succeeded. There's also no record that a failure happened at all once the exception is caught somewhere upstream (or crashes the run if it isn't).

Root cause: the loop had no failure boundary at the per-item level — only at the batch level, which is the wrong granularity for a batch of independent fetches.

Fix: fetch_prices_with_dlq() (pipeline.py) wraps each coin's fetch individually. A failure routes that coin to a DeadLetterQueue with the error and an attempt count, and the loop continues — the rest of the batch is unaffected. replay_dlq() retries just the dead-lettered coins later, removing them from the DLQ on success.

Prevention: tests/test_dead_letter_queue.py — an xfail test proving the naive batch loses a successful result (bitcoin) when a later item (ethereum) fails, plus tests confirming the DLQ isolates the failure correctly and that replay recovers once the simulated transient condition clears.

Issue #4 — Fully materializing a large stream before processing loses all progress on a mid-stream failure

Found: while stress-testing the pipeline against a longer synthetic historical-price backfill and simulating the kind of mid-fetch failure a real paginated API produces on a large pull.

Impact: the naive processor calls list(stream) before doing anything else — the entire stream must be read successfully before a single record is usable. If the stream fails at record 350 of a 1,000-record backfill, all 350 already-produced records are discarded along with the failure; there's no partial result to inspect or resume from.

Root cause: processing was written as "read everything, then process everything" instead of "process as it arrives" — a reasonable simplification for a small, reliable stream, but not for the kind of large, occasionally-flaky stream this pipeline is meant to survive.

Fix: process_chunked() (pipeline.py) processes the stream in bounded chunks (default 100 records), flushing each completed chunk before reading the next. A failure mid-stream loses at most the current in-flight chunk, not everything already processed, and the caller gets back exactly how many records were processed and why it stopped.

Prevention: tests/test_chunked_processing.py — an xfail test proving the naive version returns nothing at all on a mid-stream failure (it can't — it never got the chance to return), plus a test confirming the chunked version preserves the 3 already-completed chunks (300 of 1,000 records) when the 4th chunk hits the same simulated failure.

Note on framing: the benefit demonstrated and tested here is partial-progress preservation and bounded blast radius on failure — the more concrete, testable version of "process in chunks so a big pull doesn't take everything down with it." A literal peak-memory reduction claim isn't made or tested; that's a real secondary benefit of chunking but isn't what this test suite proves, and this log doesn't claim more than what's actually verified.

After — pipelines/crypto/pipeline.py (the fix, current on main)

"""
Crypto pipeline — multi-coin price batch fetch + historical-stream aggregation.

Same I/O/logic separation as the finance pipeline (see its module docstring) —
unit tests exercise the logic deterministically; `python pipeline.py --live` hits
the real CoinGecko public API (no key required).

Two production issues are fixed here; see BUILD_LOG.md for the full postmortem on each:
  3. Dead-letter queue + replay (fetch_prices_with_dlq, replay_dlq)
  4. Chunked processing at scale (process_chunked)
"""
from __future__ import annotations

import time
from dataclasses import dataclass, field
from typing import Callable, Iterable, Iterator

import requests

COINGECKO_SIMPLE_PRICE_URL = "https://api.coingecko.com/api/v3/simple/price"


@dataclass
class DeadLetter:
    coin_id: str
    error: str
    attempts: int = 1


@dataclass
class DeadLetterQueue:
    """Fix for issue #3: a place failed fetches go, instead of vanishing. Nothing
    that failed to ingest is ever silently absent from the run's record — it's either
    in the results or it's in the DLQ with a reason.
    """

    entries: dict[str, DeadLetter] = field(default_factory=dict)

    def add(self, coin_id: str, error: Exception) -> None:
        if coin_id in self.entries:
            self.entries[coin_id].attempts += 1
            self.entries[coin_id].error = str(error)
        else:
            self.entries[coin_id] = DeadLetter(coin_id=coin_id, error=str(error))

    def remove(self, coin_id: str) -> None:
        self.entries.pop(coin_id, None)

    def coin_ids(self) -> list[str]:
        return list(self.entries.keys())


def fetch_prices_with_dlq(
    coin_ids: list[str],
    fetch_one: Callable[[str], float],
    dlq: DeadLetterQueue,
) -> dict[str, float]:
    """Fetches each coin independently. A failure on one coin is routed to the DLQ
    and does not abort the rest of the batch — the fix for issue #3.
    """
    results: dict[str, float] = {}
    for coin_id in coin_ids:
        try:
            results[coin_id] = fetch_one(coin_id)
        except Exception as exc:  # noqa: BLE001 — this is the DLQ boundary by design
            dlq.add(coin_id, exc)
    return results


def replay_dlq(dlq: DeadLetterQueue, fetch_one: Callable[[str], float]) -> dict[str, float]:
    """Retries every coin currently in the DLQ. Coins that succeed on replay are
    removed from the DLQ and returned; coins that fail again stay in the DLQ with
    an incremented attempt count.
    """
    recovered: dict[str, float] = {}
    for coin_id in dlq.coin_ids():
        try:
            recovered[coin_id] = fetch_one(coin_id)
            dlq.remove(coin_id)
        except Exception as exc:  # noqa: BLE001
            dlq.add(coin_id, exc)
    return recovered


def process_chunked(
    stream: Iterator[dict],
    chunk_size: int = 100,
) -> tuple[list[float], int, str | None]:
    """Fix for issue #4: processes a potentially-large record stream in bounded
    chunks instead of materializing it all at once. Returns (prices_processed_so_far,
    count_processed, error_message_or_None) — a chunk that fails does not discard the
    work already completed in prior chunks, and the caller learns exactly how far
    the run got instead of losing everything.
    """
    processed: list[float] = []
    error: str | None = None
    chunk: list[dict] = []

    def flush(chunk: list[dict]) -> None:
        for record in chunk:
            processed.append(record["price"])

    try:
        for record in stream:
            chunk.append(record)
            if len(chunk) >= chunk_size:
                flush(chunk)
                chunk = []
        flush(chunk)  # final partial chunk
    except Exception as exc:  # noqa: BLE001 — reading the next record OR flushing the current chunk
        # can fail (e.g. the paginated fetch breaks mid-stream, or a record in the
        # current chunk is malformed); either way, only the in-flight chunk is at
        # risk, and any of that chunk already appended to `processed` before the
        # failure is kept, not discarded.
        error = str(exc)

    return processed, len(processed), error


def fetch_one_live(coin_id: str) -> float:
    resp = requests.get(
        COINGECKO_SIMPLE_PRICE_URL,
        params={"ids": coin_id, "vs_currencies": "usd"},
        timeout=10,
    )
    resp.raise_for_status()
    data = resp.json()
    if coin_id not in data or "usd" not in data[coin_id]:
        raise ValueError(f"CoinGecko returned no USD price for {coin_id!r}")
    return data[coin_id]["usd"]


if __name__ == "__main__":
    import sys

    if "--live" in sys.argv:
        dlq = DeadLetterQueue()
        coins = ["bitcoin", "ethereum", "not-a-real-coin-id"]  # last one deliberately fails
        results = fetch_prices_with_dlq(coins, fetch_one_live, dlq)
        print("Fetched:", results)
        print("Dead-lettered:", dlq.coin_ids())
        time.sleep(1)
        recovered = replay_dlq(dlq, fetch_one_live)
        print("Recovered on replay:", recovered, "(expected empty — that coin id is genuinely invalid)")
    else:
        print("Run with --live to hit the real CoinGecko endpoint. "
              "See tests/ for deterministic unit tests of the DLQ/chunking logic.")
