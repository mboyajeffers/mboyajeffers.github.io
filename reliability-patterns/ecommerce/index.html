Ecommerce Pipeline

What it does: validates an incoming product catalog before computing a KPI from it, and tracks order changes with a full audit history (live catalog source: fakestoreapi.com, a public demo product API standing in for a real merchant feed — no key required).

Architecture, in 5 lines: fetch_live_catalog() hits the network → validate_catalog() partitions records into valid / rejected-with-reason → average_price() computes only over the valid subset and reports both counts → separately, OrderStore.update_order() never overwrites silently — every real change appends an immutable AuditEntry alongside updating current state.

What this proves — see BUILD_LOG.md for the full postmortem on each: 1. Schema/data validation gate — malformed upstream records (null/non-numeric price, negative price, empty title) are rejected with a specific reason before they can reach a KPI, not silently included or crashing the run. 2. Immutable audit trail — "what was this order's price before the correction, and when did it change" always has an answer.

Run it yourself:

pip install -r ../../requirements.txt
pytest tests/ -v          # deterministic, no network required
python pipeline.py --live # hits the real fakestoreapi.com endpoint

What this is / isn't: a small demonstration pipeline built to make two specific, realistic production failure modes concrete and testable — not a claim that this is any specific merchant's actual integration. The malformed catalog records used in tests are synthetic and disclosed as such.

Build Log — the postmortem

Build Log — Ecommerce Pipeline

Postmortem-style log (Issue / Impact / Root Cause / Fix / Prevention) — see ../../EVALUATION_RUBRIC.md.

Issue #5 — No validation gate before computing a catalog KPI

Found: while testing the average-price calculation against a catalog containing a handful of malformed records (synthetic, disclosed — see pipeline.py's module docstring and tests/test_validation_gate.py), representative of what a real merchant feed occasionally contains: a null price, a price serialized as "N/A", an empty title, a negative price from a refund artifact.

Impact: the naive average crashes outright on the first non-numeric price (TypeError), or — in a looser implementation that coerced types instead of crashing — would silently compute a wrong number by including a refund-artifact negative price in the average. Either way, the KPI is not trustworthy until every upstream record is known-good, which a real feed rarely guarantees.

Root cause: the pipeline treated "received a record" as equivalent to "record is safe to compute on." Those are different claims, and only the second one should ever reach a KPI.

Fix: validate_catalog() (pipeline.py) partitions incoming records into valid and rejected (each rejection carrying a specific reason: missing/empty title, non-numeric price, negative price). average_price() computes only over valid and reports both counts, so a KPI consumer can see at a glance how much of the feed was actually usable.

Prevention: tests/test_validation_gate.py — an xfail test proving the naive average crashes on the malformed catalog, plus tests confirming the validation gate's partition and reasons are exactly right, and that the KPI is computed only over the valid subset.

Addendum, found during a scrutiny pass on this pipeline itself (2026-08-17): the first version of validate_record() checked isinstance(price, (int, float)) and price < 0 — both of which float('nan') and float('inf') pass through. NaN in particular is the classic silent-corruption value: it's a legitimate float, and NaN < 0 evaluates False (NaN compares false to everything, including itself), so neither check catches it, and any sum it touches becomes NaN with no exception raised. Fixed with an explicit math.isfinite() check, added to validate_record() before the negativity check. New test: test_validation_gate_rejects_nan_and_inf_prices.

Issue #6 — Order updates have no history

Found: while modeling a price correction on an existing order (a common, mundane operation — a pricing error gets fixed after the order is placed) and asking "what was this order's price before the correction, and when did it change?"

Impact: the naive order store mutates the current-state dict in place. Once an update runs, the prior value is gone — there is no way to reconstruct what changed, when, or from what, which is exactly the question a reconciliation review, a customer dispute, or a chargeback investigation asks first.

Root cause: "update the order" was implemented as "overwrite the order," conflating current state with the full history of how it got there. Those are two different data models, and only tracking the first one throws away information nothing else in the system can recover.

Fix: OrderStore (pipeline.py) keeps current state as before, but every field change that actually changes a value also appends an immutable AuditEntry (field, old value, new value, timestamp) to a separate log. history(order_id) reconstructs the full sequence of changes for an order; no-op updates (setting a field to the value it already has) are correctly not logged as a change.

Prevention: tests/test_audit_trail.py — an xfail test proving the naive store has no way to answer the history question at all, plus tests confirming the fixed store logs exactly the real changes in order, correctly ignores no-op updates, and that current() still reflects the latest state.

After — pipelines/ecommerce/pipeline.py (the fix, current on main)

"""
Ecommerce pipeline — product catalog validation + order audit trail.

Same I/O/logic separation as the other pipelines. Live source: fakestoreapi.com, a
public demo product-catalog API (no key) — explicitly a stand-in for a real merchant
feed (Shopify Admin API, a marketplace API, etc.), not a claim that this is any real
merchant's integration. The malformed records used to prove the validation gate are
synthetic, injected deliberately, and disclosed as such here and in BUILD_LOG.md.

Two production issues are fixed here; see BUILD_LOG.md for the full postmortem on each:
  5. Schema/data validation gate (validate_catalog, average_price)
  6. Immutable audit trail (OrderStore)
"""
from __future__ import annotations

import math
import time
from dataclasses import dataclass, field

import requests

FAKESTORE_PRODUCTS_URL = "https://fakestoreapi.com/products"


@dataclass
class ValidRecordsResult:
    valid: list[dict]
    rejected: list[tuple[dict, str]]  # (raw_record, reason)


def validate_record(raw: dict) -> str | None:
    """Returns None if the record is valid, or a human-readable rejection reason.

    This is the validation gate: a record either passes and is safe to compute on,
    or it's rejected with a reason and never touches a downstream KPI.
    """
    price = raw.get("price")
    title = raw.get("title")

    if not isinstance(title, str) or not title.strip():
        return "missing or empty title"
    if not isinstance(price, (int, float)) or isinstance(price, bool):
        return f"price is not numeric (got {type(price).__name__}: {price!r})"
    if not math.isfinite(price):
        # NaN and +/-inf both pass a naive `isinstance(price, float)` check, and NaN
        # passes a naive `price < 0` check too (NaN compares False to everything,
        # including itself) -- either one silently poisons any downstream sum.
        return f"price is not finite ({price!r})"
    if price < 0:
        return f"price is negative ({price!r})"
    return None


def validate_catalog(raw_records: list[dict]) -> ValidRecordsResult:
    """Fix for issue #5: partitions raw records into valid / rejected-with-reason
    instead of letting malformed data reach a KPI computation silently.
    """
    valid: list[dict] = []
    rejected: list[tuple[dict, str]] = []
    for raw in raw_records:
        reason = validate_record(raw)
        if reason is None:
            valid.append(raw)
        else:
            rejected.append((raw, reason))
    return ValidRecordsResult(valid=valid, rejected=rejected)


def average_price(raw_records: list[dict]) -> tuple[float, int, int]:
    """Returns (average_price_of_valid_records, valid_count, rejected_count)."""
    result = validate_catalog(raw_records)
    if not result.valid:
        raise ValueError("no valid records to average — every record was rejected")
    avg = sum(r["price"] for r in result.valid) / len(result.valid)
    return avg, len(result.valid), len(result.rejected)


@dataclass
class AuditEntry:
    order_id: str
    field: str
    old_value: object
    new_value: object
    ts: float


@dataclass
class OrderStore:
    """Fix for issue #6: every change to an order is recorded as an immutable,
    timestamped audit entry in addition to updating current state — "why did this
    number change" always has an answer.
    """

    _current: dict[str, dict] = field(default_factory=dict)
    _audit_log: list[AuditEntry] = field(default_factory=list)

    def create_order(self, order_id: str, **fields: object) -> None:
        self._current[order_id] = dict(fields)

    def update_order(self, order_id: str, **changes: object) -> None:
        order = self._current[order_id]
        for field_name, new_value in changes.items():
            old_value = order.get(field_name)
            if old_value != new_value:
                self._audit_log.append(
                    AuditEntry(order_id=order_id, field=field_name, old_value=old_value,
                               new_value=new_value, ts=time.time())
                )
                order[field_name] = new_value

    def current(self, order_id: str) -> dict:
        return dict(self._current[order_id])

    def history(self, order_id: str) -> list[AuditEntry]:
        return [e for e in self._audit_log if e.order_id == order_id]


def fetch_live_catalog() -> list[dict]:
    resp = requests.get(FAKESTORE_PRODUCTS_URL, timeout=10)
    resp.raise_for_status()
    return resp.json()


if __name__ == "__main__":
    import sys

    if "--live" in sys.argv:
        catalog = fetch_live_catalog()
        avg, valid_count, rejected_count = average_price(catalog)
        print(f"Average price across {valid_count} valid products "
              f"({rejected_count} rejected): ${avg:.2f}")
    else:
        print("Run with --live to hit the real fakestoreapi.com endpoint. "
              "See tests/ for deterministic unit tests of the validation/audit logic.")
