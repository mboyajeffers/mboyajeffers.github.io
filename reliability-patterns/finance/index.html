Finance Pipeline

What it does: ingests daily closing prices for a small set of equities (live source: Yahoo Finance's public chart endpoint, no API key — same source used elsewhere in this account's financial-data-engineering and the live market-pulse dashboard) and computes a portfolio total.

Architecture, in 5 lines: fetch_live_bar() hits the network → returns a plain PriceRecord → PriceLedger.ingest() stores it idempotently, keyed on (symbol, date) → normalize_price() converts every record to a common unit (USD) → portfolio_value() sums the normalized records. I/O and logic are deliberately separate (see pipeline.py's module docstring) so the logic is unit-testable without a network call.

What this proves — see BUILD_LOG.md for the full postmortem on each: 1. Idempotent ingestion under retry — a retried fetch for a price already on the ledger is a no-op, not a duplicate row. 2. Currency/unit normalization correctness — a GBX-quoted (LSE pence) line item and a USD line item are never summed without conversion; an unrecognized currency fails loudly instead of guessing.

Run it yourself:

pip install -r ../../requirements.txt
pytest tests/ -v          # deterministic, no network required
python pipeline.py --live # hits the real Yahoo Finance endpoint

What this is / isn't: a small demonstration pipeline built to make two specific, realistic production failure modes concrete and testable — not a trading system, not investment advice, not a claim that this is any specific employer's actual architecture. The FX rate used is static/illustrative, not a live feed (flagged in code).

Build Log — the postmortem

Build Log — Finance Pipeline

Postmortem-style log, not a changelog: each entry is Issue / Impact / Root Cause / Fix / Prevention, the same shape a real incident review uses. See ../../EVALUATION_RUBRIC.md for what this log is demonstrating structurally (rubric #9 — incident-response discipline).

Issue #1 — Duplicate price records on ingestion retry

Found: during a simulated network-retry test against PriceLedgerNaive (before/ingest_naive.py).

Impact: any transient failure between "fetch succeeded" and "caller acknowledged the write" causes a retry to re-deliver the same day's price record. The naive ledger appends unconditionally, so the same (symbol, date) pair produces two rows. Any downstream aggregate keyed off row count (trade count, naive volume sum) silently doubles for that day.

Root cause: no identity key on ingestion. The ledger trusted "I received a record" as equivalent to "this is a new record," which is only true if the network never retries — it does.

Fix: PriceLedger.ingest() (pipeline.py) keys on (symbol, date) — the natural identity of "one closing price per symbol per day" — and treats a re-delivery of an existing key as a no-op, returning False instead of silently accepting it as new.

Prevention: tests/test_idempotent_ingestion.py pins this behavior with three tests: one (xfail, strict=True) that fails against the naive implementation for the documented reason, one that asserts the fixed implementation reports [True, False] for a genuine-then-repeated record, and one added after a self-review pass (2026-08-17) that catches a second way this could still go wrong — see the addendum below.

Addendum, found during a scrutiny pass on this pipeline itself: the first version of the fix treated any second write under an existing (symbol, date) key as "already ingested, ignore it" — which is correct for a true retry (same value redelivered) but silently drops a genuine correction too (a different value arriving under the same key). That's the exact class of bug this pipeline exists to close, just relocated. Fixed: ingest() now compares the incoming value against what's already on the ledger — an exact match is a no-op (the retry case), a mismatch raises ValueError instead of guessing which value is right. A rejected conflict never applies, so the ledger's prior value stays intact.

Issue #2 — Silent currency/unit corruption in portfolio aggregation

Found: while extending the pipeline to hold more than one symbol — noticed the portfolio total for a 2-line mixed-market portfolio (AAPL/USD + VOD.L/GBX) was off by roughly 22x from a manually-computed sanity check (7027.50 naive vs. 313.86 correct — the GBX-to-GBP minor-unit conversion itself is exactly 100x by definition; the ~22x figure is this specific portfolio's blended, data-dependent total).

Impact: the London Stock Exchange quotes prices in GBX (pence), not GBP — a well-known gotcha, not a contrived one. A naive aggregator that sums raw quoted close values treats a GBX-quoted line item as if it were GBP (100x too high on that line) and any GBP line item as if it were USD (currency mismatch on top of that). The portfolio total is wrong, silently, with no error or warning — the kind of bug that only surfaces when someone manually checks the number against a brokerage statement.

Root cause: the pipeline combined values before normalizing them to a common unit. Aggregation and unit conversion were never actually the same step, they just looked like it because both operations were one line of code.

Fix: normalize_price() converts every record to USD before it's allowed anywhere near a sum, using an explicit CURRENCY_TO_USD table that includes the GBX minor-unit scale factor. normalize_price() raises on an unrecognized currency rather than defaulting to a guessed rate — a loud failure here is strictly better than a quiet wrong number in a portfolio report.

Prevention: tests/test_currency_normalization.py — an xfail test proving the naive aggregation is wrong by more than 5% (it's actually wrong by ~95%), plus direct tests on normalize_price() for the GBX conversion math and for the loud-failure-on-unknown-currency behavior.

What this pipeline does not claim

This is a demonstration pipeline built to make these two failure modes concrete and testable, not a production trading or portfolio-accounting system. The FX rate table is static/illustrative — a real build would source it from a live FX feed and version it, the same way pipeline.py's docstring already flags.

"""
BEFORE — issue #1: non-idempotent ingestion.

Kept intact (not deleted after the fix) so BUILD_LOG.md's claim is checkable: run

from __future__ import annotations

from dataclasses import dataclass, field

from pipelines.finance.pipeline import PriceRecord


@dataclass
class PriceLedgerNaive:
    """Appends every ingested record with no de-duplication. A retried fetch for a
    (symbol, date) pair already on the ledger produces a second row — silently
    double-counting that day in any downstream sum (e.g. daily volume, trade count).
    """

    def ingest(self, record: PriceRecord) -> bool:
        self._records.append(record)
        return True  # always reports "new" — this is the bug

    def all_records(self) -> list[PriceRecord]:
        return list(self._records)

    def count(self) -> int:
        return len(self._records)

After — pipelines/finance/pipeline.py (the fix, current on main)

"""
Finance pipeline — daily price ingestion + portfolio valuation.

Design note (testing discipline, see EVALUATION_RUBRIC.md #3): I/O (fetch_live_bar) is
kept separate from pure logic (PriceLedger, normalize_price, portfolio_value) so the
logic that actually matters for correctness can be unit-tested deterministically,
without hitting a live network endpoint in CI. Run `python pipeline.py --live` to
exercise the real Yahoo Finance fetch path locally.

Two production issues are fixed here; see BUILD_LOG.md for the full postmortem on each:
  1. Idempotent ingestion under retry (PriceLedger.ingest)
  2. Currency/unit normalization correctness (normalize_price, portfolio_value)
"""
from __future__ import annotations

import time
from dataclasses import dataclass, field

import requests

YAHOO_CHART_URL = "https://query1.finance.yahoo.com/v8/finance/chart/{symbol}"

# Real, well-known gotcha: the London Stock Exchange quotes in GBX (pence), not GBP.
# A US stock like AAPL quotes in USD. Summing raw quoted prices across a portfolio
# that holds both without normalizing currency AND minor-unit scale silently produces
# a portfolio value that's off by orders of magnitude for GBX-quoted names.
CURRENCY_TO_USD = {
    "USD": 1.0,
    "GBP": 1.27,   # illustrative static rate — a live build would pull this from an FX feed
    "GBX": 1.27 / 100.0,  # GBX is 1/100th of GBP
}


@dataclass
class PriceRecord:
    symbol: str
    date: str  # YYYY-MM-DD
    close: float
    currency: str  # "USD", "GBP", "GBX", ...


@dataclass
class PriceLedger:
    """Idempotent, append-only store of ingested daily price records.

    Fix for issue #1 (BUILD_LOG.md): ingest() is keyed on (symbol, date), the natural
    identity of "one closing price per symbol per day." A retried fetch for a record
    already present is a no-op, not a duplicate row.

    Idempotency is about tolerating a *retry of the same event*, not about silently
    accepting a different value under the same key -- those are different situations
    and conflating them would just move the silent-corruption risk from issue #1 to a
    new one. If a second write under an existing key carries a genuinely different
    close price, that's either a real correction (should be explicit) or a data-quality
    problem (should be loud) -- either way, ingest() raises rather than guessing.
    """

    _records: dict[tuple[str, str], PriceRecord] = field(default_factory=dict)

    def ingest(self, record: PriceRecord) -> bool:
        """Returns True if this was a new record, False if it was an exact repeat
        of an already-ingested record. Raises ValueError if the same (symbol, date)
        key arrives with a different close price or currency -- a conflict, not a
        retry, and conflicts must never be resolved silently.
        """
        key = (record.symbol, record.date)
        if key in self._records:
            existing = self._records[key]
            if existing.close != record.close or existing.currency != record.currency:
                raise ValueError(
                    f"Conflicting price for {record.symbol} on {record.date}: "
                    f"ledger has {existing.close} {existing.currency}, "
                    f"got {record.close} {record.currency}. This is not a retry -- "
                    "resolve explicitly (e.g. an authorized correction path), don't "
                    "silently overwrite or silently drop."
                )
            return False
        self._records[key] = record
        return True

    def all_records(self) -> list[PriceRecord]:
        return list(self._records.values())

    def count(self) -> int:
        return len(self._records)


def normalize_price(record: PriceRecord) -> float:
    """Fix for issue #2: convert a quoted price to a common unit (USD) before it is
    ever combined with another instrument's price. Raises on an unrecognized currency
    rather than silently treating it as USD — a wrong number should be loud, not quiet.
    """
    if record.currency not in CURRENCY_TO_USD:
        raise ValueError(
            f"Unrecognized currency {record.currency!r} for {record.symbol} — "
            "refusing to guess an exchange rate."
        )
    return record.close * CURRENCY_TO_USD[record.currency]


def portfolio_value(records: list[PriceRecord]) -> float:
    """Sum of normalized (USD) values — safe to call across a multi-currency portfolio."""
    return sum(normalize_price(r) for r in records)


def fetch_live_bar(symbol: str, retries: int = 3, backoff_seconds: float = 1.0) -> PriceRecord:
    """Live path — hits the real Yahoo Finance chart endpoint (no API key required,
    same source already used in this account's `financial-data-engineering` and the
    live `market-pulse` dashboard). Retries on transient failure; the retry is exactly
    what makes issue #1's idempotency fix necessary in the first place.
    """
    last_exc: Exception | None = None
    for attempt in range(retries):
        try:
            resp = requests.get(
                YAHOO_CHART_URL.format(symbol=symbol),
                params={"range": "5d", "interval": "1d"},
                headers={"User-Agent": "Mozilla/5.0"},
                timeout=10,
            )
            resp.raise_for_status()
            payload = resp.json()["chart"]["result"][0]
            meta = payload["meta"]
            closes = payload["indicators"]["quote"][0]["close"]
            timestamps = payload["timestamp"]
            last_close = next(c for c in reversed(closes) if c is not None)
            last_ts = timestamps[-1]
            date_str = time.strftime("%Y-%m-%d", time.gmtime(last_ts))
            currency = meta.get("currency", "USD")
            return PriceRecord(symbol=symbol, date=date_str, close=last_close, currency=currency)
        except Exception as exc:  # noqa: BLE001 — deliberately broad: this is the retry boundary
            last_exc = exc
            if attempt < retries - 1:
                time.sleep(backoff_seconds * (2**attempt))
    raise RuntimeError(f"Failed to fetch {symbol} after {retries} attempts") from last_exc


if __name__ == "__main__":
    import sys

    if "--live" in sys.argv:
        ledger = PriceLedger()
        for sym in ("AAPL", "VOD.L"):  # VOD.L is GBX-quoted on the LSE
            rec = fetch_live_bar(sym)
            is_new = ledger.ingest(rec)
            print(f"{sym}: {rec.close} {rec.currency} (new={is_new})")
        print(f"Portfolio value (USD): {portfolio_value(ledger.all_records()):.2f}")
    else:
        print("Run with --live to hit the real Yahoo Finance endpoint. "
              "See tests/ for deterministic unit tests of the ingestion/currency logic.")
